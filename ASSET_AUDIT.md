# ShieldQuest visual asset audit

**Scope** · 20 November 2026 · `feature/landing-page` working tree on commit `0a6f3e3`, including the uncommitted prototype and the existing browser build. The main inventory covers assets referenced by the active game and the Tiled editor map. The history section records assets from the preceding app snapshot that could be reintroduced later.

**Result** · The active characters and scenery are drawn from local code and map data. The dependency fonts and icons have identified upstream licences. The release gaps are missing third-party notice texts in the inspected output and incomplete records for the reference material that informed the UI. Press Start 2P has a documented commercial-game glyph lineage and warrants review despite the distributed font’s OFL licence. The inspected current game code showed no imported commercial-game sprite, tile sheet, or texture. This audit documents observable provenance and licence terms. It does not establish chain of title or legal clearance.

## Evidence and risk labels

- **LOW** means the available evidence supports locally authored construction or an identified licence suitable for the intended use if its conditions are met.
- **REVIEW** means a source, underlying right, or distribution condition needs verification.
- **HIGH** means there is affirmative evidence of potentially unauthorised copying. No inspected entry met that threshold.

For first-party rows, **Project terms** refers to [ShieldQuest’s proprietary licence](LICENSE). It claims Team SecurePi ownership and requires Team SecurePi’s prior written permission for third-party redistribution, commercial distribution, and hosting. It sets no separate per-asset public credit requirement for the project art. It expressly preserves third-party licences. A project ownership statement and contributor warranty are documentary evidence, and neither independently proves that every referenced design or uncommitted contribution belongs to the project. The implementation record and rendering code establish the construction method for the active local art. Individual human asset authors and reference rights are recorded as unknown where the repository does not identify them.

## Distribution checks

- **Asset locations and loading.** Neither `public/assets/` nor `src/assets/` exists in the active working tree. The only standalone image in `src/` is `src/game/maps/ground.png`. There are no standalone SVGs, external image URLs, CSS image URLs, imported sprite sheets, or legacy texture packs in the active app source. The background CSS uses colours and gradients. Font URLs come from installed Fontsource CSS and resolve to local build files. Links in repository documents and package licence URLs do not load artwork into the game.
- **Dependencies.** `package.json` and `package-lock.json` identify the visual packages above. The runtime also declares MIT-licensed React and React DOM 19.3.1. The lockfile identifies MIT-licensed `scheduler@0.28.0` and `eventemitter3@5.0.4` in the runtime dependency graph. Vite, its React plugin, TypeScript and React type packages are build or type tooling. They supply no authored game artwork. Include licences for dependencies actually shipped in the browser bundles. [React MIT licence](https://raw.githubusercontent.com/facebook/react/v19.3.1/LICENSE)
- **Release notices.** Full licences are available in the installed packages. The inspected `dist/` and its `feedback-check/` sub-build contain no standalone third-party notices or licence texts. The reviewed JavaScript includes brief licence headers, and the inspected WOFF files contain author notices and OFL URLs. Those WOFF records did not expose the full OFL text. Include the complete applicable notices with distributable builds rather than relying on package metadata, embedded URLs, or brief headers. The root licence expressly keeps third-party terms separate.
- **Public release authority.** Treat Team SecurePi’s approval to distribute the game under its proprietary terms as a separate question from compliance with the font, icon and engine licences. The report cannot verify rights from resemblance alone or confirm that an asset has no earlier source.

## Summary and recommended actions

- **Appears suitable to retain.** Keep the procedural player, customisation layers, NPCs, active map and tiles, buildings, roads, trees, furniture, minimart assets, and local UI primitives under the project’s distribution terms. Retain Outfit and Lucide with complete third-party notices. Historical CC0 packs can be considered separately if their exact files are verified.
- **Requires verification.** Confirm who owns the supplied Figma designs and which references contributors had permission to use. Review Press Start 2P’s documented arcade glyph lineage and preserve its OFL notice. For historical sprites and tiles with unknown source terms, retain them as historical records pending evidence.
- **Potential replacements.** No current sprite, tile or prop was identified as requiring replacement based on the inspected evidence. Choose an independently sourced heading font if the Press Start 2P lineage cannot be resolved for release. Replace any unknown-source legacy artwork that the team intends to restore if documentation cannot be recovered.
- **Missing documentation.** Publish complete licence and copyright notices for the active bundled fonts, Lucide and applicable Feather portions, Phaser, React and relevant bundled dependencies. Keep a source register recording asset creator, original URL or authoring record, acquisition date and version, applicable licence, modifications, and required notice. Preserve the source design and contributor permission records alongside the register.
